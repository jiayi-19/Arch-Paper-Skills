# Revision, rebuttal, and delivery

## Revision scope

For a local edit, preserve facts, metric values, terminology, macros, citations and
surrounding argument. If an existing statement is unsupported, identify the source
gap and use the strongest currently defensible wording; do not silently alter data.
For a full rewrite, map paragraph roles first and remove repetition by assigning each
argument a clear home. A brief original -> revision -> reason table is useful when
the wording change affects meaning, not obligatory for grammar edits.

Resolve necessary research facts from the code or artifacts already supplied before
asking the author to re-enter them. Missing evidence can remain an explicit TODO in
a draft while independent sections advance. Avoid repeated intake forms or asking
for a headline result that the study has not yet produced.

## Reviewer feedback and rebuttals

Turn each reviewer concern into a specific disputed claim, assumption or missing
comparison. Answer with the relevant mechanism or available evidence, identify a
manuscript change, and distinguish a completed new experiment from a proposed one.
A response can correct a misunderstanding without promising unperformed measurements.

When reviews conflict, prioritize the paper's actual research question and explain
the tradeoff to the author. Do not convert speculative future work into a rebuttal
result or reveal author identity under anonymous review. Verify current venue rules
when they constrain response content or new experiments.

## LaTeX and bibliography

Read the existing source layout, macros and bibliography before editing. Keep edits
in the authorized isolated workspace. Preserve labels when possible; update their
references if a section changes role. Cite a key only after checking the actual paper
and adding or locating its real bibliography entry. Complete author lists according
to the current venue rules. A related title or search snippet does not verify a DOI.

`python3 scripts/check_manuscript.py /path/to/main.tex` checks ordinary literal LaTeX
inputs, citation keys, labels, references and drafting placeholders. It is not a TeX
engine, and macro-generated paths/citations require manual inspection. Dynamic macro
arguments are reported as unverified. It neither compiles nor renders.

Current official submission instructions override remembered conference formats.
Preserve bundled classes, anonymity, paper size and required review settings; obtain
an actual submission number from the author rather than inventing one. Do not move
mandatory scope qualifiers out of the abstract just to make it sound stronger.

## Session workflow and delivery

Honor the user's established render/push preferences. If local rendering is disabled,
perform useful source and evidence checks and use the authorized remote workflow.
Do not install TeX or compile a PDF merely because a generic paper workflow does so.
A skill activation alone grants no permission to push, email, publish or run costly
research experiments.

Return the requested draft or reviewable edits, the checks actually performed, and
material evidence gaps. Keep workflow commentary, private paths, draft instructions
and reviewer notes out of final anonymous manuscript prose. Do not create unrelated
reports for every small change. Skill/reference examples use English; discussion
with the author can use their language.
