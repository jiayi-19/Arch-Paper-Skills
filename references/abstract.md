# Abstract construction

Use the annotated development distribution in [corpus profile](corpus-profile.md)
as context, not a mandatory length or sentence count. Match current venue limits.

Three useful drafts from the same evidence:

- **Gap-led:** concrete setting -> residual problem and reason -> insight/mechanism
  -> strongest finished result with comparator and scope.
- **Direct:** research object and capability -> restriction it removes -> key operation
  -> validated outcome or finding.
- **Insight-led:** observed property -> why it changes the design choice -> mechanism
  -> evidence and relevant operating condition.

For a characterization, tool or benchmark, the central result may be an empirical
finding, validated modeling capability or executable task interface rather than speedup.
An early draft without measurements can state the problem and method with pending
result text. Material scope, such as layer-only execution or a constrained theorem,
belongs with the main statement. Detailed failure analysis can remain in Evaluation.

Write one sentence per necessary argument move, not one sentence per module. Compare
alternatives for clarity and accuracy; do not produce all variants unless useful.
Run `check_draft.py --section abstract` and examine the development profile. A useful
short abstract or technical detail is not wrong because it lies outside p10-p90.
